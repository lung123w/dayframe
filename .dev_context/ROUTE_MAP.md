## 1. UI surfaces

There is **no client-side router**. `App.jsx` holds `activeView` and renders one view at a time inside one shared shell: `TopStrip.jsx` is the 52px strip that switches the view and `CaptureLine.jsx` is the shell's single capture line, present on every view (`src/App.jsx` mounts both in `.app-chrome`). `activeView` defaults to **`today`** — Today is the cold open (`src/App.jsx:41`).

**Stage 2 of `ui-modernization-calm-canvas` (ADR-013)** replaced the 220px rail (`Sidebar.jsx`/`.css`, now `TopStrip.jsx`/`.css`) with the strip: four text destinations (Today · Week · Habits · Review) plus a **"More" overflow** built on `@radix-ui/react-dropdown-menu` holding Finance · Projects · Backup · Notifications. That also closes the audit's F16 mobile dead end — the old rail was `display: none` below 768px (`Sidebar.css:93-98`), while the strip is one responsive row that wraps and keeps all six views reachable at 1440 / 768 / 420px.

**Stage 3 of `ui-modernization-calm-canvas` (ADR-013)** turns the list surfaces into rows: Today, the Week view's day columns and the backlog render one hairline-separated line per entry (title at body size, right-aligned muted metadata) with no card fill, colour stripe or shadow, and every row action (move up/down, defer, edit) is reachable by keyboard focus and by touch — the actions appear on `:focus-within` as well as `:hover`, and are always visible where `@media (hover: none)` matches, so no row action depends on hover alone (F10). Popovers in these surfaces are Radix: `TimePopover`, `RepsPopover`, `DeferPopover` and the heat-map popover render through `RadixPopover.jsx` (viewport clamping, portal, Escape and outside dismissal), and icon-only actions use `TooltipButton.jsx`. Logging a habit is one action: a single activation on a not-done row writes the day with zero minutes and the duration is an optional in-place refinement (PUT), never a second POST (ADR-008's 409).

**Stage 4 of `ui-modernization-calm-canvas` (ADR-013)** makes every confirmation, alert and prompt an in-app dialog and gives each persisting surface one reserved save-status line. `AppDialog.jsx` (new) is the single shell — it wraps `@radix-ui/react-dialog` and exports `AppDialog` (the shell), `ConfirmDialog` (the `window.confirm`/`window.alert` replacement; `cancelLabel={null}` renders the one-action alert) and `PromptDialog` (the `window.prompt` replacement) — owning the focus trap, Escape dismissal and focus return. **There is now no `window.confirm`, `window.alert` or `window.prompt` call site under `src/`** (`ProjectsView.jsx`'s project delete, `ProjectModal.jsx`'s project delete, `App.jsx`'s task delete and backup-failure notice, `WeeklyReview.jsx`'s objectives-replacement confirm and "nothing to sync" alert, `RichTextEditor.jsx`'s link-URL prompt all render it), and `TaskModal` / `HabitModal` / `ProjectModal` render their shells through it too — which is what gives those three Escape dismissal. `SaveStatus.jsx` + `useDebouncedSave.js` are the other pair: typing a persisted field is written 500 ms after the last keystroke (flushed on blur, on week change and on unmount) and reported in one reserved `role="status"` line reading `Saving…` / `Saved` / `Could not save — retry`. In the review, the two windows are now named — **Planning week 〈dates〉** (the document, goals and the key-events grid) and **Reviewed week 〈dates〉** (`weekStart − 1`, the habit chips) — and the Week view's day buttons and each day column's header set a view-local focused day (F20), which used to be dead controls.

**Stage 5 of `ui-modernization-calm-canvas` (ADR-013)** adds no surface and no route: it is a **keyboard layer** over the six views that already exist plus one **droppable** overlay. `src/components/keyboard.js` freezes the key map (`design.md` §6 D10 — `/`, `j`/`k`, `x`, `t`, `u`, `g` then `t/w/h/r/f/p`, `Escape`, `Ctrl/⌘ + K`) and the guards every handler reads; `src/components/useKeyboardLayer.js` registers the app-level half once from `App.jsx` (`j`/`k`, the `g` chord, `Ctrl/⌘ + K`) and mounts nothing. The **command palette** is `CommandPalette.jsx` — a Radix dialog listing the six `activeView` destinations plus the one action the map exposes (focus the capture line), opened by `Ctrl/⌘ + K` or closed by picking an item / `Escape`. It is the change's last slice and is **droppable**: its component, its mount in `App.jsx` and that one key entry are the whole thing. **Discoverability:** the palette's footer renders the key map itself, so the shortcuts are documented in the app and not only in this file; `ARCHITECTURE.md` §4.6 carries the handler-by-handler registration table. The layer sets the same six `activeView` values — no router, no new view key, and no app-level state beyond `App.jsx`'s `paletteOpen` boolean.

## 2. REST API

Base `http://localhost:3001/api` · JSON in/out · **no auth** (local single-user app) · `express.json({ limit: '50mb' })` for base64 images (`server/index.js:25`) · **no CORS middleware** (same-origin in dev via the Vite proxy and in prod via the Express static host). Routers are mounted in `server/index.js:28-43`; each file lives in `server/routes/`.

## 3. Conventions

- **Period parameters are explicit**: `?weekStart=YYYY-MM-DD` (week, Monday-start), `?from=&to=` (habit entries, key events), `?date=` (daily notes, workflow completions), `?monthKey=YYYY-MM` (finance), `?year=` (yearly goals). Never infer "the current period" silently — the caller says which period it wants.
- **A missing period is not an error**: the read endpoints return an in-memory default document rather than 404. The one exception is `GET /api/monthly-reviews/current`, which **creates** the row. Anything that assumes a "GET is read-only" contract is wrong here.
- **Dates are `YYYY-MM-DD` strings, Hong Kong time.** No server-side "today" assumptions in period math; the server's only date logic is `getLastSaturdayOfMonth` / `currentMonthKey` from the shared `src/utils/lastSaturday.js`.
- **Validation errors** return HTTP 400 with `{"error": "…"}`; unknown ids return 404; duplicate `monthKey` and duplicate habit entry return **409**. `mode` values outside `personal|work` are rejected with 400 on the WORK-toggle branch.
- **List endpoints must not ship base64 blobs.** When adding an image field, strip it from list responses and expose it on detail endpoints only (`monthlyReviews.js:29-33`).
- **Real-world identifiers never live in tracked source.** Seed/reference data that carries account numbers goes in a gitignored file under `data/` (`data/seed-cards.json` for cards), read at runtime; the endpoint must behave correctly when that file is missing (POL-006 — the GitHub repo is public).
- **No DELETE for document tables** (`weekly_reviews`, `weekly_objectives`, `monthly_reviews`, `yearly_goals`, `daily_notes`): clear content by upserting an empty document.
- **Two key-event UIs exist** — the review view's day grid and the planner's `WeeklyObjectives` grid — both writing `/api/key-events`. A change to key events must be checked in both.
- **Confirmations are in-app, never native** (stage 4, ADR-013 / design.md §3 D7). A destructive action opens `ConfirmDialog`, which traps focus, closes on Escape **without issuing a write**, and returns focus to the control that opened it. There is no `window.confirm`, `window.alert` or `window.prompt` call site under `src/`; `window.open` for an external link is not a dialog and stays.
- **Writes are debounced, and their state is visible** (stage 4, design.md §8 D12). Use `useDebouncedSave` for anything the user types into a persisted field (500 ms after the last keystroke, flushed on blur, on period change and on unmount) and render `SaveStatus` in a reserved position — `Saving…` / `Saved` (fades after ~2 s) / `Could not save — retry`. Discrete actions (a checkbox, an add, a remove) may still write immediately. A surface must never write once per keystroke.
- **The keyboard layer is additive and has one owner per key** (stage 5, design.md §6 D10). A new shortcut goes in `src/components/keyboard.js`'s map first, then in the ONE place that can honour it — never in two document listeners. A row opts in with `tabIndex={0}` + `data-kbd-row` and its surface marks the container `data-kbd-list`; row keys must call the surface's own existing handler (so the pointer path and the keyboard path write the same state), and a handler must return early when `isTypingContext(document.activeElement)` or `isOverlayOpen()` is true (except `Escape`, which belongs to the overlay). `preventDefault()` only on a key the handler acted on; never on Tab.
